# Приложение Д — Playbook реагирования на инциденты безопасности

**Область:** локальный контур «Нейро-сметчик». Владелец процесса — администратор ИБ; заместитель — MLOps/DevOps. Все действия фиксируются в append-only `security_audit_log`.

## 1. Классификация и SLA реакции

| Уровень | Пример | Обнаружение | Реакция | Уведомление |
|---|---|---|---|---|
| P1 Критический | подтверждённая утечка данных, выход LLM-трафика вовне, подмена весов модели | firewall/audit/drift | немедленная изоляция контура, ≤15 мин | администратор + руководитель, высокий приоритет |
| P2 Высокий | успешный prompt injection, массовые галлюцинации цен, нарушение hash-chain аудита | injection-детектор, валидация, `verify_audit_chain()` | ≤1 ч, откат промпта/модели | администратор + ML-инженер |
| P3 Средний | серия неудачных попыток injection, аномальные цены, дрейф >2 %, отказ vLLM | мониторинг, drift check | ≤1 рабочий день | сметчик-куратор + ML-инженер |
| P4 Низкий | разовые ошибки валидации, таймауты уточнения | UI, журнал | планово | сметчик |

## 2. Сценарий A — Prompt injection / попытка извлечения системного промпта

1. Детектор (`security.sanitize_text`) находит паттерн → запрос отклонён HTTP 400, `code=prompt_injection_blocked`.
2. В `security_audit_log` пишется событие `prompt_injection_blocked` с `severity=critical`, `trace_id`, актёром и списком паттернов.
3. Orchestrator создаёт запись `pipeline_execution_log (step=parser, status=blocked)`.
4. При ≥5 попыток за 10 минут от одного актёра — rate limiter блокирует, администратор получает уведомление `high`.
5. **Расследование:** `GET /api/v1/admin/trace/{trace_id}`, `GET /api/v1/admin/audit`; проверить, не попал ли текст в few-shot/обучающую выборку.
6. **Коррекция:** добавить паттерн в `INJECTION_PATTERNS`, обновить версию промпта, прогнать red teaming + golden set, выпустить canary.
7. Если атака прошла в ответ модели — откатить версию промпта (`POST /prompts/activate`), аннулировать затронутые черновики, пересоздать версии смет.

## 3. Сценарий B — Галлюцинации цен / расценок

1. Триггер: позиция без `catalog_id`, `hallucinated_catalog_ref`, аномальное отклонение цены >35 %, жалоба сметчика.
2. Немедленно заблокировать утверждение смет (ошибка уровня `error`).
3. Проверить `price_catalog.updated_at`, `rate_catalog_sources.legal_status`, версию KB.
4. Откатить KB/промпт/модель до последней версии с `drift_checks.verdict=ok`.
5. Пересоздать смету (новая версия), уведомить заказчика, записать инцидент в Feedback Loop.

## 4. Сценарий C — Утечка / внешний трафик

1. Firewall/сетевой аудит фиксирует обращение к внешнему AI-API.
2. Немедленно отключить egress, остановить воркеры LLM, перевести систему в ручной режим (`LLM_ENABLED=false`).
3. Проверить `llm_inference_log` за период: какие запросы и персональные данные могли быть переданы.
4. Сохранить дамп логов (append-only), проверить hash-chain, уведомить ответственного по 152-ФЗ.
5. Ротация ключей/секретов в Vault, смена VPN-доступов, аудит учётных записей.

## 5. Сценарий D — Нарушение целостности аудита

1. `verify_audit_chain()` → `False` / `GET /api/v1/admin/audit` → `chain_valid=false`.
2. Считать P2. Заморозить релизы, снять дамп БД только на чтение, сравнить с последним backup.
3. Найти первый `id` с несовпадением; проверить, не было ли прямого доступа к SQLite/PostgreSQL в обход API.
4. Восстановить БД из проверенного backup (RPO ≤1 ч, RTO ≤4 ч), провести повторную верификацию.

## 6. Сценарий E — Компрометация учётной записи / увольнение

1. Немедленная блокировка `users.active=0`, отзыв VPN/MFA токенов, разрыв активных сессий.
2. Проверка `security_audit_log` по актёру за 30 дней; экспорт неизменяемой копии.
3. Смена секретов, ротация ключей MinIO/PostgreSQL, проверка прав роли.
4. Для смет, подписанных скомпрометированным актёром — повторное утверждение по принципу «четырёх глаз».

## 7. Чек-лист после инцидента (обязателен для закрытия)

- [ ] Инцидент зафиксирован в `security_audit_log` с `severity` и `trace_id`.
- [ ] Проверена целостность hash-chain аудита.
- [ ] Проверен `llm_inference_log` за период инцидента (retention ≥12 мес.).
- [ ] Выполнен golden-прогон: регрессия не хуже baseline −2 %.
- [ ] Выполнен red teaming по обновлённому чек-листу OWASP LLM Top-10.
- [ ] Обновлены промпты/политики/правила firewall; версии зафиксированы.
- [ ] Проведено внеплановое тестирование восстановления из backup.
- [ ] Материалы переданы Product Owner и куратору качества; политика использования AI обновлена.

## 8. Контакты и артефакты

| Роль | Ответственность | Артефакт |
|---|---|---|
| Администратор ИБ | P1/P2, ротация секретов | `security_audit_log`, копия логов |
| MLOps/DevOps | изоляция контура, restore | `drift_checks`, backup snapshot |
| Backend/ML | промпты, модель, golden set | `prompt_versions`, `model_versions` |
| Domain Expert | проверка затронутых смет | `llm_corrections`, Feedback Loop |
| Product Owner | коммуникация с заказчиком | отчёт инцидента |
